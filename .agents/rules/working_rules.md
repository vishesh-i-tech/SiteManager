# Workspace Collaboration & Working Rules

Always follow these rules strictly throughout our project collaboration:

### 1. Language Rule
- Even if the user speaks or types in Hindi (or Hinglish), **ALWAYS reply in clear, professional English**.

### 2. Phased Development
- Implement changes step-by-step in structured phases (one phase at a time). Do not attempt to implement everything at once. Keep progress incremental, verified, and well-organized.

### 3. Git & GitHub Tracking
- Always stage, commit, and push changes to the project's GitHub repository after each phase or modification so the user's GitHub contribution graph stays active and up to date.

### 4. Quick Response Time
- Do not delay chat responses by waiting synchronously on long Git operations. Respond promptly. Run background pushes when needed or right after code changes, and send a clear notice confirming when the push is complete.

### 5. Technology & Architecture Explainer File (`explainer.md`)
- Maintain and update `explainer.md` in the project root.
- For every technology, library, or major change introduced, document:
  - **Name of the technology**
  - **What it does (Role & Purpose)**
  - **How it works (Under the hood)**
  - **A short, simple summary**
- Keep `explainer.md` continuously updated as new features or libraries are added.
